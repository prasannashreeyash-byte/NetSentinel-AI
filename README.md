# NetSentinel AI — Security Monitoring, Dual-Role Authentication & Complaint Resolution Platform

A complete cybersecurity monitoring and incident response web application built with **React + Vite**, **Express.js**, **MongoDB + Mongoose**, **JWT Authentication**, **bcryptjs**, and **Recharts**.

---

## Architecture Overview

NetSentinel AI provides two completely distinct portals and dashboards:

1. **User Portal (`/user/login` & `/user/dashboard`)**:
   - **User Authentication**: Email & password login, public account registration (automatically assigned `user` role), and secure cryptographic token-based password reset.
   - **User Dashboard Overview**: Tracks total complaints, pending review, under-investigation, and resolved incidents.
   - **Security Problem Submission**: Allows users to report 8 categories of problems:
     - *Suspicious login attempts*
     - *Malware or virus concerns*
     - *Unauthorized access*
     - *Network problems*
     - *Application errors*
     - *Website security vulnerabilities*
     - *Source-code errors or bugs*
     - *Other cybersecurity concerns*
   - **Code & Error Reporting**: Optional error message / stack trace and source code snippet fields.
   - **Secure Supporting Attachment Upload**: File type validation (images, logs, text, json, code, pdf) and size limit (max 5 MB). Dangerous executables (`.exe`, `.bat`, etc.) are blocked.
   - **Automated Problem Guidance**: Transparent rule-based analysis (not a trained AI model) providing potential category, estimated severity, possible causes, and safe troubleshooting steps before and during submission.
   - **My Complaints Tracking**: Users can view their own complaints, inspect administrative updates, review remediation notes, and inspect verified code corrections. Users cannot edit administrative notes, status, or severity.

2. **Administrator Portal (`/admin/login` & `/admin/dashboard`)**:
   - **Admin Authentication**: Dedicated SOC administrator login. Rejects standard users (403 Forbidden).
   - **Secure CLI Admin Provisioning**: Administrators cannot be created through public registration; they are securely provisioned via CLI (`npm run seed:admin` or `node seedAdmin.js`).
   - **Preserved Existing Main Security Dashboard**:
     - *Security Overview*: Events analyzed, critical alerts, high severity, protected endpoints (128 hosts), threat risk score.
     - *Threat Activity Timeline*: Interactive 12-hour Recharts area graph.
     - *Event Distribution*: Real-time Recharts donut chart across attack vectors.
     - *Protected Endpoints & Network Map*: Segment breakdowns, gateway topologies, and sensor probes.
     - *Security Alerts & Event Table*: Filters by severity/category, live auto-refresh, CSV export, and event acknowledgement.
     - *Simulation Engine Controls*: Pause/resume synthetic demo telemetry and trigger synthetic events.
     - *Security Audit Trail*: Full log of administrative actions.
   - **Complaint Management Section**:
     - *Admin Overview Cards*: Registered users, total complaints, pending, under-investigation, resolved, and critical incidents.
     - *Comprehensive Complaint Table*: Filter by status, severity, category, or search term.
     - *Problem Investigation Panel*: Inspect user description, error logs, stack traces, and attachments.
     - *Code Error Detection & Correction*: Dedicated code viewer and editor. Allows administrators to review submitted code, write and publish suggested corrections, explain the fix, and set verification status. Untrusted code is never executed on the server.
     - *Incident Resolution Workflow*: Set severity (Low, Medium, High, Critical), status (Open, Under Investigation, Resolved, Closed), assignee, investigation findings, root cause, remediation, and resolution notes.

---

## Important Notice: Simulated Telemetry & Rule-Based Guidance

- **Simulated Intrusion Telemetry**: Security events, network map data, and traffic curves displayed on the security operations dashboard are generated by a synthetic demo simulation engine for educational and hackathon presentation purposes. No real packet sniffing or intrusion detection is performed on live production networks.
- **Rule-Based Automated Guidance**: Problem guidance provided to users upon complaint submission uses transparent, deterministic keyword and pattern matching, **not a trained AI model**. All diagnostic outputs are clearly labeled as automated guidance awaiting administrator review.

## Complete VS Code Setup Instructions

### Step 1: Open Project in VS Code
1. Open VS Code.
2. Click **File** > **Open Folder...** and select the project directory:
   `NetSentinel_AI_Submission_Updated`

### Step 2: Configure Environment Variables
1. In the `server` folder, inspect `.env.example`.
2. Ensure `server/.env` exists. If not, copy `.env.example` to `.env`:
   - PowerShell: `Copy-Item server\.env.example server\.env`
   - Bash: `cp server/.env.example server/.env`
3. Generate or configure a random `JWT_SECRET` (at least 32 characters), your `MONGODB_URI`, `ADMIN_EMAIL`, and `ADMIN_INITIAL_PASSWORD`.

> **Note**: `.env.example` files contain placeholders only. Never commit `.env` containing production passwords or secret keys.

### Step 3: Start MongoDB Service
- Ensure MongoDB is running locally:
  - Windows: Check via `Get-Service MongoDB` in PowerShell, or start it via Services.
  - Or specify your remote MongoDB Atlas connection string in `server/.env`:
    ```env
    MONGODB_URI=mongodb+srv://<user>:<password>@cluster.mongodb.net/netsentinel?retryWrites=true&w=majority
    ```

### Step 4: Provision Administrator Account via Secure Script
Run the secure provisioning script in the `server` folder:
```bash
cd server
npm install
npm run seed:admin
```
Or provision with custom CLI arguments:
```bash
node seedAdmin.js --email admin@domain.com --password "SecureAdmin2026!" --name "SOC Lead"
```
Output will confirm:
```
Connected to MongoDB at mongodb://127.0.0.1:27017/netsentinel
Administrator account successfully CREATED / UPDATED:
  Name:  prasanna
  Email: prasannashreeyash@gmail.com
  Role:  admin
You can now log in at: http://localhost:5173/admin/login
```

### Step 5: Start the Backend Server
In the `server` terminal:
```bash
npm run dev
# or: npm start
```
The server will start listening on `http://localhost:5000` and display `MongoDB connected`.

### Step 6: Start the Frontend Client
Open a **new terminal** in VS Code (Terminal > New Terminal):
```bash
cd client
npm install
npm run dev
```
Vite will start the client on `http://localhost:5173`. Open this URL in your web browser.

## API Reference

### Authentication
- `POST /api/auth/register` — Public registration (assigns `role: 'user'`).
- `POST /api/auth/login` — Sign in for standard users and administrators.
- `POST /api/auth/admin-login` — Administrator sign in (strictly rejects non-admins with 403).
- `POST /api/auth/forgot-password` — Initiates secure reset and generates 15-minute token.
- `POST /api/auth/reset-password` — Resets password with valid token.
- `GET /api/auth/me` — Returns current authenticated user session.

### Complaints & Incident Reporting
- `POST /api/reports/guidance` — Analyzes problem and returns rule-based guidance.
- `POST /api/reports` — Submits security problem with optional code snippet and validated attachment. Generates unique complaint ID (`NS-COMP-*`).
- `GET /api/reports` — Lists complaints (users see only their own; administrators see all).
- `GET /api/reports/stats` — Overview metrics for dashboard cards.
- `GET /api/reports/:id` — Detailed complaint view (ownership enforced).
- `PATCH /api/reports/:id` — Administrator-only: updates status, severity, findings, cause, remediation, code correction, and resolution notes.

### Security Monitoring & Simulation (Administrator)
- `GET /api/events` — Simulated security events with category & severity filters.
- `GET /api/dashboard` — Telemetry timeline, risk score, and category distribution.
- `POST /api/events/:id/acknowledge` — Acknowledges active security alert.
- `POST /api/demo/tick` — Generates synthetic security event.
- `POST /api/demo/control` — Pauses or resumes simulation engine.
- `GET /api/admin/overview` — Aggregated counts: users, complaints, open, under investigation, resolved, critical incidents.
- `GET /api/admin/users` — List of registered accounts.
- `GET /api/admin/audit` — Immutable administrator action audit log.
